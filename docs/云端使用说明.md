# 云端使用与维护

临期助手以 OpenClaw 工作区技能接入现有机器人，复用现有微信渠道和模型。微信账号配置没有改动。

## 在微信里使用

直接向原来的机器人说，例如：

- “临期助手，登记2盒牛奶，2026年10月10日到期，放冷藏。”
- “临期助手，查一下库存。”
- “牛奶喝了一盒。”（有同名多批时，需要明确机器人返回的 #物品ID）
- “撤销刚才用掉一盒的操作。”
- “#1 已经扔掉了。”
- “刚才那盒药的有效期是2027年3月31日，放常温。”

物品ID是永久编号。写入成功后会显示数量、日期和储存方式；没有日期的药品先追问，超时后按“待核实”保存，不推算一年有效期。

当前已接入文字库存操作。云端模型配置声明仅支持 text，尚未配置独立图像模型；照片识别未在本次验收中完成。先发文字使用，不能把图片识别视为已经可用。

## 云端位置

- 代码：`~/.openclaw/workspace/apps/ai-pantry/`
- 技能：`~/.openclaw/workspace/skills/ai-pantry/SKILL.md`
- 正式数据：`~/.local/share/ai-pantry/inventory.sqlite3`
- 测试数据：`~/.local/share/ai-pantry/test.sqlite3`（永不参与真实提醒）
- 备份：`~/.local/share/ai-pantry/backups/`（每日首轮扫描时使用SQLite backup API生成）
- 投递配置：`~/.local/share/ai-pantry/delivery.json`（账号路由信息，本机私有；不复制微信令牌）
- 联调记录：`~/.local/share/ai-pantry/test-reports/`

这些是服务器路径，不是Mac路径。业务数据库、令牌、账号路由和会话记录均不进入Git。

## 定时任务

`ai-pantry.timer` 每5分钟启动一次扫描，处理一小时草稿兜底。每日提醒从上海时间09:30开始发送；22:00到次日08:00不发送。服务停机错过09:30时，当日安静时段前恢复可补发当日提醒，旧日提醒不会批量补发。

提前预告与到期后的三次提醒分开计数；三次后只在周一跟进。物品一直保留，直到明确用完或丢弃。提醒通过 OpenClaw 的现有 `message send` 接口发送，不另建微信机器人，也不让模型自行计数。

维护命令（在服务器执行）：

```sh
systemctl --user status ai-pantry.timer --no-pager
journalctl --user -u ai-pantry.service -n 30 --no-pager
systemctl --user disable --now ai-pantry.timer
```

最后一条暂停提醒，不停止原有 OpenClaw 或微信机器人。

## 投递异常

为避免消息可能已发出后反复重发，发送失败或回执无法确认时，程序将保存 `delivery-attempt.json` 并暂停后续投递，日志显示 `needs_reconciliation`。库存录入仍可使用，`status`接口也会返回 `reminder_needs_attention:true`。

需先核对指定提醒是否实际送达，再由维护人员处理该记录。确认已送达时将state设为delivered，让下一轮补记ack；确认未送达时将state设为acknowledged，让后续扫描重试。不要在发送器运行中手动改记录；不要未经核对直接清空记录或伪造ack。

当前是单机MVP，没有给发送异常单独配置第二告警渠道；可通过服务日志和技能status查询。多实例并发与自动故障告警是后续工作。

## 测试与更新

```sh
cd ~/.openclaw/workspace/apps/ai-pantry
python3 -m unittest discover -s tests -v
python3 -m pantry.worker --dry-run
python3 scripts/test_openclaw.py
```

最后一条会通过现有模型执行真实工具调用，但全部使用 `--test` 库，且没有 `--deliver`，不会发送微信测试消息。它会产生正常的模型调用用量。联调脚本每次使用唯一测试物品名和独立会话，避免覆盖其他测试。

`--dry-run` 会扫描正式数据、生成队列和每日备份，但不会发送消息或增加成功提醒次数。

更新部署脚本仅修改本项目路径；旧代码保留在 `~/.local/share/ai-pantry/releases/`，数据库放在代码目录以外，重新部署不会覆盖库存。程序不需要公开HTTP端口，也不需要重启OpenClaw网关。
