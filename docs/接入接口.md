# 渠道适配接口 v0.1

在项目目录运行 `python3 -m pantry --db .local/pantry.sqlite3 --household home --actor owner`，从stdin传入一个JSON对象，stdout返回一个JSON对象。参数不可拼接用户输入到shell；集成应使用 subprocess 参数数组与 stdin，或直接调用 Pantry.execute。

成功返回 `ok:true`；字段错误返回 `ok:false,error`，进程退出码1。不根据模型口头输出认定写入成功。

## 命令

| action | 字段 | 说明 |
|---|---|---|
| list | 无 | 当前未处理库存 |
| get | item_id | 读取指定物品 |
| drafts | 无 | 读取本人的待补充/超时草稿 |
| history | 无 | 本人最近20次操作事件 |
| add | item | 登记新批次 |
| update | item_id, changes | 修改指定ID，不按模糊名称直接修改 |
| consume / discard | item_id, quantity可选 | 不传数量表示全部处理 |
| undo | event_id | 撤销本人操作；后续已有变更则拒绝 |
| draft | item | 草稿，等待一小时 |
| resolve | draft_id, changes | 补充草稿；超时后修改原库存 |
| tick | 无 | 执行超时与提醒扫描，不发送消息 |
| outbox | 无 | 读取等待发送的通知 |
| ack | delivery_id | 仅渠道明确成功后调用 |

所有写操作（包括tick、ack）必须有request_id。渠道用账号+原消息ID+稳定的子操作序号构造，不用每次重试生成的新随机ID。定时任务用任务执行槽ID；ack用delivery ID。重复ID携带不同内容会拒绝，适配器需保存首次解析结果再重试。

item字段：name必填；category=food/medicine/other；quantity为正数（默认1）；unit默认件；storage=room/fridge/freezer/unknown；expiry为YYYY-MM-DD或null；date_source=label/user/estimate/unknown；basis为日期依据原文或规则说明。

完整读取返回永久item ID。新增和修改还返回event_id，供撤销。保存永久ID与原渠道消息的对应关系。数字回复只有引用上下文唯一时才可执行。

## 调度与发信顺序

1. 每5分钟tick处理草稿；提醒扫描也可执行，但发送器只在每天09:30发送pre/due/weekly/unknown类型。
2. fallback类通知可即时发送；其他类按照配置的家庭时间发送。
3. 发送前再次确认outbox中该条目仍处于queued；合并同一家庭的提醒。
4. 发送成功后ack每个delivery；失败保留队列并退避，不假装成功。
5. 服务重启重新读取outbox，不依赖内存中的提醒计数。

单次tick会创建当前日期的提醒；接入层负责发送时段。客户端必须使用真实当前时间，生产CLI没有伪造日期参数。

## OpenClaw业务桥接器

`integrations/openclaw/pantry_bridge.py` 使用固定home/owner和独立生产库，仅开放业务操作；不向模型开放tick、outbox或ack。`--test`选用隔离库。新增/草稿必须显式给出category、quantity、unit、storage，避免默认值掩盖漏提取。缺关键字段的add会自动转为draft，除非用户明确要求直接保存未知、调用方传入save_unknown:true。

写入结果增加saved_summary和missing_fields，供模型核对真实保存结果。status可读上海日期与提醒是否需要人工核对。
